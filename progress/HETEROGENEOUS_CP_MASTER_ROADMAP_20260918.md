# Hybrid 序列与层联合动态 CP Roadmap

当前研究固定 GDN:GQA=3:1。联合选择完整输入的组批、分层 CP、rank 组与 token 放置，在完整训练显存预算下提高每卡有效 TFLOP/s／MFU；固定输入与分配卡数时等价于最小化更新时间。N 为未修改调度逻辑的 Megatron 原生 dynamic CP，并保留连续 GDN 段布局；二维拥有全部现有执行自由度。

事实与结果只以 [当前归档](ARCHIVE-20261016.md) 为准。本页是研究优先级。用户已明确恢复 H100 GPU 实验；首轮依赖失败经用户安装 TileLang 后解除。第二轮 14 项已完成并清理，包含 12 个有效项、2 个显存预算拒绝；随后用户另授权的 16 卡、四点模块扩展性实验也已完成并清理。后续环境问题仍须立即报告、不得自行修复。

数据、二维性能模型与调度器的对应关系，以及可运行的 CPU 接手检查，见 [CODEX_HANDOFF.md](CODEX_HANDOFF.md)。历史 H800 CP 扩展性原始表随代码保留；H100 后续使用硬件证据索引 `experiments/sequence_dynamic_cp/configs/cp_evidence_sources.json` 中的 H100 数据，未测范围明确标为未校准。

## 已有核心结论

- **H800 正例。** 224Ki＋4Ki 可变 N-K14 优于固定 N-K24，二维再增加约 29.3% 吞吐；256Ki 的 72 条有限容量消融与 568 条短批重打包分别保留约 24.1% / 24.8% 吞吐收益。历史原始证据继续保留。
- **H100 迁移反例。** 224Ki、不规则长度、192Ki 三组的冻结二维分别比已测最快 N 降低 34.95%、31.79%、40.42% 吞吐；三组均存在同时更快、allocated 与 required 更低的 N 候选。结论限于当前有限候选，不排除其他二维计划。
- **执行器控制。** H100 224Ki 同一 N-K14 计划通过 joint executor 仅慢约 1.26%；通用执行器固定开销不足以解释原二维约 53.72% 的时间增量。分项模块 CP 响应已有下述锚点，组批、token 放置与路由对整步差距的贡献仍未分别测量。
- **评分迁移。** 原 H800 响应模型在前两组选错；纯计算量在最终候选池中选对前两组，但 192Ki 所选 N-K12 比最快 N-K24 慢约 13.09%。H100 四点响应已接入独立模型与调度器，回溯 13 个候选时在 224Ki/192Ki 选中已测最快可行 N；不规则输入仍有显存准入误判和 K16/K20 排序错误，尚未完成广泛输入的独立评分消融。
- **H100 模块实测。** 固定 256Ki，GQA 从节点内 CP8 到跨节点 CP16 的延迟比为 1.50–1.53×，GDN chunkwise 为 1.81–1.87×；卡数翻倍后每卡 TFLOP/s／MFU 分别降至 CP8 的 75.10%–76.54% / 90.28%–93.34%，均无性能收益；小输入 CP 一致性检查通过。GQA 的延迟方向与同长度旧 H800 锚点相反，直接证实旧响应不可照搬；历史 GDN 配置不匹配，尚不能比较其跨硬件变化。
- **在线范围。** 实际在线 N/二维选择未接入；短运行的训练合同通过不代替数值等价、长期收敛和在线净收益验证。
- **CP32 新证据。** 用户将窗口延长至 23:50；CP32 两模块与 GDN-only 方差复核完成，共 5.231 GPU·小时，23:45 已清理。GQA32 为 221.343719ms，GDN32 合并全部 3+7 次为 10.643056ms；相对 CP16 每卡效率为 69.02%/67.50%。GDN 的 CP8→16 优势不能外推到 CP16→32。新 `joint_32gpu_h100.json` 已接入，旧 H800 和 CP8/16 锚点保留。
- **优势场景筛查。** 33 个输入/卡数组合中，完整 N 候选比较的最优预测增益约 +1.08%，来自 16 卡不规则中长输入；模型峰值约 70.22→66.62GiB。三个弱正例均补扫区间内全部 32-token 对齐 K。32 卡没有有意义且对照完整的优势候选；一个 +1.85% 候选因 8 个 N 容量不可评分而比较未决。当前均是 CPU 预测，不能宣称完整训练收益。

## 评价规则

以按分配 GPU 数归一的每卡有效 TFLOP/s 或 MFU 判断性能收益。相同工作量和硬件下效率比为 `(p_old*T_old)/(p_new*T_new)`；卡数翻倍而时间未减半为效率损失，不写成“加速收益”。恰好减半维持效率，更短才提高效率。延迟、容量和显存另列，完整计划计入所有分配卡及等待。固定 16 卡、相同输入的 N/二维训练对照保持原有排序，因为其时间比与每卡效率比等价。

## 按最小实验推进

1. **补足 H100 模型并验证排序。** `configs/joint_16gpu_h100.json` 与 `joint_32gpu_h100.json` 已分别接入 CP8/16/32 实测；旧 H800 配置原样保留。下一阶段重点是跨长度/packing 工作量外推、CP1/2/4、MLP/路由/更新与显存误差，当前约 1% 的候选收益小于已知模型误差。选择最小补充点并保留验证输入，不用整步结果反调系数再宣称验证成功。
2. **验证重新求解的二维计划。** 新配置已接入 `joint_cp_search.py --hardware H100`，两个小输入 CPU 独立求解/replay 与真实 CLI 通过，保留完整二维自由度。后续生成目标输入的新计划，与明确声明的 N 容量集合比较。先验证完整训练预算和有限输入上的每卡效率，再扩展随机长度分布；不把冻结旧计划的失败推广为整个方法无效。
3. **检验评分模型的独立价值。** 固定候选集合、执行器及共同显存规则，比较计算量与含算子 CP 响应、路由、完整显存的评分。计入预测错误和实际准入拒绝；本轮迁移诊断作为反例保留，不挑选正例覆盖。
4. **实现实际在线选择。** 在评分与候选质量可信后，接入每 batch 的可变容量 N/二维选择，计入决策和切换成本，以总有效 FLOPs/总 GPU·时间及对应 MFU 评价，同时保留 tokens/墙钟；固定卡数和相同输入时两种排序等价。缓存区分形状、算子与拓扑。单机仅在能回答明确机制问题时补充，不直接把需要 CP16 的 N-K14 搬到 8 卡。

保持完整训练、统一实际显存保护与真实 N。模型预算和实际显存分开报告；不把偏好规则拒绝写成物理不可行。α=2 的显存交换规则是可选部署偏好，双方使用共同固定参考；本轮 H100 候选评分未应用该偏好，物理预算始终独立生效。

## 方法与未完成部分

组内 S=ΣL、Q=ΣL²；GQA 时间可写为 `(aQ+bS)/p+R_GQA`，GDN 为 `cS/p+R_GDN`。R 表示输入、内核与拓扑相关响应；已含通信不重复计费。联合评价组间最大时间、边界搬运及跨 F/B 的存活显存，不能由某层局部加速直接推出整步收益。

H800 迁移先验保留为历史配置，H100 已有独立 CP8/16/32 响应及显式外推模型；仍有排序和显存误判，尚未验证广泛输入排序和在线净收益。模型与接口可后续扩展稀疏注意力，但近期继续固定 3:1。独立 HybridModel 类集成、训练正确性和长期收敛属于后续工程/论文证据，不作为本轮追加 GPU 任务。
