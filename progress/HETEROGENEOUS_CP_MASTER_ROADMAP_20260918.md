# Heterogeneous CP — Master Roadmap

**当前决策：冻结扩展 TMF/cohort，主线集中在 Dynamic CP 已开启条件下的 GDN sequence-wise child CP。** 当前实现已经接入完整 Megatron 训练，并在单机8卡与双机16卡的直接动态CP基线上得到明确的正向步时结果。无本地token上限的子组策略在 D8-P2 和 D16-P2 上分别取得约 **48.0%** 和 **16.6%** 的吞吐收益；带17408 token上限的策略在显存接近基线时仍分别取得约 **5.7%** 和 **3.8%** 的收益。下一阶段从“证明是否可能有收益”转为“解释收益、控制显存、自动选择子组并扩大可复现优势场景”。按既定正式验收合同，这两个场景仍各只有一次完整运行，尚未计入“至少10个独立正式强优势场景”。

本文件为本次方向的最新状态入口；旧 roadmap 保留作历史，不沿用其中已过期的“尚未接入/尚未采集”等状态。实现完成、训练跑通、数值等价和性能验收分别判断。

## 1. 已完成与当前边界

- **完整训练入口**：原生 `pretrain_gpt.py` 路径，THD/变长 packing、独立序列标签/位置/prompt mask；不是单独 attention benchmark。使用当前已验证的无物理 padding 配方。
- **动态父组与异构激活布局**：GQA 使用 `DefaultDynamicCPScheduler` 按当前打包输入选出的运行时 parent CP；完整序列再分配到父组内的嵌套 child groups，GDN 整层的投影、MLP、残差随 child token 归属。连续3层 GDN 保持布局，只在段边界转换；即使首层是 GDN，也从 parent 输入布局转换进入。
- **反向与状态域**：可微 all-to-all，反向执行逆路由；参数/梯度同步仍在原 DP×CP 域。缩小激活 CP 不等于缩小优化器同步域。
- **子组创建已修正**：所有 WORLD ranks 按一致顺序创建各 parent 的子组，再保留本 rank 所属组；支持 WORLD16/parent CP8 等多个 parent 组。
- **两套对照命名**：早期静态父组实验保留 U/UC/S，其中 U=原 uniform、UC=parent CP不变且合并连续GDN转换、S=sequence-wise child CP；最新直接实验使用 DU/DS/DC，其中 DU=开启 Dynamic CP、关闭 GDN child CP，DS=在同一动态父组上启用无本地token上限的child CP，DC=启用child CP并设置17408 token上限。两套数据不混算，当前发明和优化的直接基线是 DU。
- **监测/复测**：已实现 FWD/BWD NVTX hooks、手动复测启动器与 SQLite 分析；现有 trace 没有 HCP/ 标签，不能宣称部署端 hooks 已验证生效。
- **动态选择已跑通**：child规模可随运行时parent、序列数量、物理长度和本地token预算变化。已有轨迹直接记录 CP8→2×CP4 和 CP16→4×CP4，设计与现有选择器还支持 CP8→4×CP2 等多子组几何，方案不限定为 CP16→2×CP8。
- **未完成**：面向实际代价的自动策略仍未完成；当前选择规则主要按最小可行child和固定token上限决策，尚未共同预测负载、转换、拓扑、显存及collective重叠。4096隐藏维度配置还缺少逐项输出/梯度/更新数值对照，双节点临界路径、checkpoint恢复和正式交替重复验收也待补充。本机按用户要求只做静态/语法和离线数据分析，不跑 GPU 训练。

## 2. 指导后续实验的有效数据

K=1024；不同模型/配方的绝对步时不可横比。profile 步时多数是优化器事件间隔；不是无 profiler 的独立重复基准。

### 2.1 已确定存在收益的 Dynamic CP 场景

最新手工实验使用16层、隐藏维度4096、BF16、完整激活重计算的GQA/GDN混合模型。DU、DS、DC三种模式保持同一输入、模型和Dynamic CP父组选择；表中平均步时取第11—30步，吞吐收益按 `DU步时/方案步时-1` 计算。所有运行均完成30步训练并正常退出。

| 场景 | 输入与动态几何 | DU | DS及收益 | DC及收益 | 当前结论 |
|---|---|---:|---:|---:|---|
| **D8-P2，单机8卡** | 5条序列 `[66560,31744,16384,8192,8192]`；parent CP8。DS按选择规则可用4×CP2；4096维DC轨迹为2×CP4，每卡物理token为16640/16128 | 4143.6 ms；最高allocated约36.4 GB | **2799.2 ms；吞吐+48.0%**；最高allocated约42.2 GB | **3920.6 ms；吞吐+5.7%**；最高allocated约36.3 GB | 已确认child CP在Dynamic CP基线上可以显著降步时；DS以约5.8 GB额外峰值显存换取更高吞吐，DC说明显存约束下仍可保留小幅收益 |
| **D16-P2，双机16卡** | 6条序列 `[132096,64512,32768,16384,8192,8192]`；parent CP16。选择规则可形成4×CP4；已有小模型轨迹直接记录该几何 | 5745.3 ms；最高allocated约33.5 GB | **4927.3 ms；吞吐+16.6%**；最高allocated约39.2 GB | **5535.7 ms；吞吐+3.8%**；最高allocated约33.3 GB | 已确认收益可延伸到双节点Dynamic CP父组；现有数据尚不能把收益全部归因于节点内child通信，需profile分解 |

这里的“已确定收益”指同配置完整训练中，DS/DC相对DU均得到正向步时结果，不再只是原型或容量候选。它不等同于完成正式统计验收：每种配置目前只有一次完整运行，尚缺交替顺序的独立重复。D16的4×CP4直接轨迹来自较小隐藏维度配置；4096维性能日志支持正向步时，但不能替代同配置的逐步路由轨迹。

配套数值核验方面，四卡真实GQA/GDN、隐藏维度512、SGD、完整重计算的对照已经通过输出、梯度和更新后权重容差；分组与反向路径也覆盖可变父组、路由往返、参数梯度及更新路径。它支持实现语义，但4096维分布式优化器配置仍需补正式数值对照。

| Agent C-013 | U/UC OOM；S完成20步训练，随后评估缓存报错 | 容量收益候选，非完整成功、非正式速度胜例 |
| 16卡、24层、72K+56K，UC/S | 3961.17→4122.81 ms，S步时+4.08%；allocated 69.37→71.84 GiB | S的GPU2/4/5/6稳态频繁malloc/free；GPU6空闲327 ms/步 |
| **16卡、24层、64K+64K，UC/S** | **合并第3–10、13–20步：3897.14→3843.64 ms，吞吐+1.39%** | 当前最干净同数据对照；前/后窗口均正收益，仍各一次运行 |

**当前等长 case 的机制证据（仅节点0）：**

- 两组均无稳态 malloc/free；最大 allocated UC=69.363、S=68.989 GiB。每卡8K，GDN核心grid相同，计算耗时基本相同。
- 第11步 GDN相关前后向 AllGather 共72次：kernel时长之和 **168.12→7.32 ms**；UC其中151.51 ms与参数收集/梯度归约重叠。不能把差额直接当整步收益，也不能认为重叠部分全部免费。
- 稳态GPU0候选布局转换类别都是24次/步，时长之和 **306.40→357.51 ms**；D2D额外约1.28 ms/步。S缺显式转换标签，51 ms差额不是已证实的固有转换增量。
- 同窗口净账：非NCCL计算+2.26 ms，只有NCCL活跃−56.41 ms，无kernel活跃+5.56 ms，最终步时 **−48.59 ms**。GQA CP16与参数/梯度同步仍是主要共同开销；NCCL时长包含等待。
- **新增确定结论：64K+64K时，UC的parent_contiguous与S的child布局完全等价。** 用本地纯路由函数比较全部16rank的64条edge，源/目标rank、偏移、长度均一致；理论转换流量相同。两条转换实现却分别使用索引重排与cat/逐片copy，存在可消除的实现差异。
- 新profile没有可靠的正式稳态 TFLOPs/s/GPU 汇总；下一轮补齐，不从旧CSV直接抄数。

## 3. 已退出的尝试、被纠正的判断

| 退出/纠正项 | 原因与保留边界 |
|---|---|
| 继续增加TMF/cohort宽度作为主要显存解法 | 128K、CP8→2、K4无重算发生OOM；冻结该主线，不代表数学上否定cohort |
| 原型/单模块提速代替完整训练收益 | 只能诊断；正式结果必须包含forward、backward、全局梯度同步和optimizer |
| 当前TE配置下引入序列间padding的THD方案 | 曾使FlashAttention被禁用；当前用对齐、无物理padding配方，不泛化成所有TE版本均不支持 |
| 只在parent成员内调用new_group | 不符合当前全局创建流程要求，已修正；保留多parent组检查 |
| 以原U作为唯一基线，或认为相同转换次数就同成本 | UC已消除重复转换；必须分离布局合并与缩组收益 |
| “更小CP必然有更快算子/更少显存” | 等长时每卡tokens/heads可能不变；不等长则整层及激活工作量失衡 |
| “agent的无收益一定是统计造假/开关无效” | 35个DONE平均步时可由日志复算；确有重复ID、TFLOPs窗口含warmup及失败分类错误，但不足以抹去真实回退 |
| 旧UC 72K+56K与新S 64K+64K作正式优势对照 | 数据及GQA工作量不同，已由同64K+64K UC/S替代 |

不等长packing和CP4不是永久淘汰方向；它们应带负载/显存预算继续作为压力及负例，不能无条件启用split。

## 4. 下一步优化计划（按优先级）

| 优先级 | 工作 | 验收与停止条件 |
|---|---|---|
| **P0：证据闭环** | 固化 D8-P2、D16-P2 的 DU/DS/DC 输入、模型和统计窗口；补4096维输出、梯度、参数更新及checkpoint恢复核验；性能运行与profile分开 | 保留当前正向结果，但不在独立重复完成前升级为稳定收益。正式性能验收继续采用交替顺序与独立配对，不把单次运行的逐步数据当重复样本 |
| **P1：代价感知选择器** | 将child候选从“最小可行组/固定token上限”升级为段级决策。输入至少包括parent/child CP、子组最大每卡token、负载比、子组数量、是否跨节点、父子转换字节、连续GDN层数、可用显存和历史profile桶；在DS、DC和parent fallback之间选择 | 在D8-P2、D16-P2保留收益，在已知负例中自动回退。候选目标是正例吞吐损失不超过已观测收益的10%，负例相对DU回退控制在2%以内；无法可靠预测时优先fallback |
| **P2：显存与缓冲优化** | 分解DS相对DU新增显存，检查父/子视图同时存活、路由pack/unpack临时张量、重计算缓存和分布式参数缓冲；复用生命周期不重叠的buffer，并让本地token预算结合实际可用显存自动给出 | D8-P2方向性目标：将DS最高allocated从约42.2 GB压到38 GB附近，同时保持至少40%吞吐收益；D16-P2方向性目标：压到35 GB附近，同时保持至少10%收益。若buffer复用影响反向或重计算一致性则回退 |
| **P3：转换与元数据路径** | 预计算并缓存同一微批次的序列归属、真实/物理边界和正反向路由；批量完成pack/unpack，减少逐片copy、CPU元数据回读与同步。目标ownership与parent-contiguous等价时复用统一转换器，不等价时保留通用路由 | 单独测量plan、pack、collective、unpack和反向恢复。必须验证每个有效token唯一覆盖、正反向互逆、重计算复用及每peer字节量，不能只凭整步变快判断正确 |
| **P4：拓扑与通信重叠** | child选择优先考虑NVLink域和节点边界，使可行的CP16→4×CP4、CP16→2×CP8等子组尽量落在节点内；分析父子布局转换、GDN内部collective与参数收集/梯度归约的临界路径，再决定是否使用独立stream或async collective | 用D16-P2 trace确认收益来自何处。只有证明存在独立计算窗口并在整步上缩短临界路径时才接受重叠实现；不把NCCL kernel时长下降直接等同于训练步时收益 |
| **P5：场景扩展** | 系统覆盖不同parent CP、2个及更多child groups、不同长度偏斜、不同本地预算和不同连续GDN层数；保留单序列、序列数不足、严重负载不均及Dynamic CP已选小parent等负例 | 优先扩展与已确认机制相邻的场景，而非只重复CP16→2×CP8。每个新配方都有DU直接基线，并记录为何选择某个child或为何fallback |
| **P6：长期联合规划** | 将GQA的可行CP、全局DP规模和固定状态通信代价纳入联合搜索，比较更小统一CP/更大DP以及兼容ownership的attention布局 | 若更简单的统一CP/DP方案更快，则作为更强基线；不得缩小梯度状态域而遗漏跨child归约，也不得改变模型层顺序制造收益 |

### 4.1 当前最有价值的优化目标

第一目标是把DS的吞吐优势与DC的显存水平结合起来。D8-P2中，DS比DU快48.0%，但峰值allocated增加约5.8 GB；DC的峰值显存已回到DU附近，却只保留5.7%的收益。这表明child CP本身具有收益空间，而固定17408 token阈值较保守。可通过更细的候选代价估计、按实际剩余显存设置预算，以及减少父子视图临时buffer，寻找两者之间更好的工作点。

第二目标是提高双节点场景的拓扑利用率。D16-P2已经显示16.6%的DS收益，且可使用多于两个child groups。后续应比较4×CP4、2×CP8及parent fallback的临界路径，让planner同时看到子组负载和节点边界，而不是只选最小CP。该方向也能直接覆盖专利所强调的可变child CP，不会把方案限制为CP16→2×CP8。

第三目标是降低决策与布局转换的固定成本。连续GDN层已经复用child布局，下一步收益主要来自归属/路由缓存、统一等价布局转换器、批量pack/unpack和可证明有效的通信重叠。旧64K+64K等价ownership案例仍可用于验证统一转换器，但不再作为唯一优化里程碑。

**首个优化里程碑：在D8-P2和D16-P2上形成“吞吐—显存”Pareto曲线，并让代价感知选择器在DS、受限child和parent之间自动选择；同时完成4096维数值闭环。** 暂不优先重写GDN核心kernel或改变优化器状态分片。

## 5. 后续实验执行合同

- 搜索阶段A：冻结当前核心实现，只允许数据构造和已有合法参数变化，用于扩展收益/负例边界，并记录全部无收益、回退、OOM和错误。阶段A的数据冻结后进入阶段B，再开展P1—P4的planner、显存、转换及通信调优；调优后的结果建立新基线，不与阶段A混算。
- 服务器所有主动写入限制在 `/workspace/repos/Megatron-LM`，包括日志、缓存、脚本及profile；不改系统依赖或目录外文件。代码提交与实验产物分开。
- 当前主线的每个case匹配DU/DS/DC的样本、标签、mask、模型、精度、重算、全局有效batch及输入/监督tokens；不同recipe各自配DU基线。早期U/UC/S只用于对应历史实现；若后续修改转换器，应额外增加保持parent不变的转换控制，分离转换优化和缩小GDN通信域的收益。
- 粗筛后正式验收：至少5组独立配对重复、交替顺序；至少10步warmup、30步测量。DS或DC相对DU的配对speedup中位数≥1.05，run级95%区间下界>1；不将单run各步当独立重复。额外比较可行的更强普通CP/DP方案。
- 至少10个**独立正式强优势场景**仍是未完成目标。当前D8-P2、D16-P2属于已完成训练且正向的场景，但各自只有一次运行，正式计数仍为0；小幅收益、容量候选、重复seed和仅在特定统计窗口为正的结果均单独记录。
- 每run记录：源码与数据版本标识、完整命令与环境、GPU/NIC/组成员、实际parent/child选择、步时分布、同窗口TFLOPs/s/GPU及公式版本、输入/监督tokens/s、全部rank allocated/reserved与可用显存；必要时记录allocator retries、OOM和碎片统计。失败明确区分训练未完成、训练后评估失败和数值失败。
- 每次里程碑记录“改动→假设→正负case结果→接受/回退决定”，保留原日志。评估/恢复验收独立进行，不能因纯性能run关闭评估就将历史评估失败视为修复。
