# 知识库主题：固定全局负载与极限显存下的 CSA/HCA Mixed CP 分析计划

日期：2026-09-11。依据用户本轮明确纠正，本文替代上一版分析的研究目标、对照选择和执行优先级；已有原始数据及 teacher-LSE 观测继续保留。本次只更新分析与计划，未启动 GPU 实验。

项目根目录：`E:/LLM论文/mine/heterogeneous_cp`。以下相对路径均以此为根。

## 1. 研究目标与正确对照

**Mixed CP 的目标是在固定全局负载、固定 GPU 数与显存预算下，让部分注意力模块采用更高效的 CP，且不显著增加峰值显存，从而加速因容量约束而必须使用较高 CP 的 fixed 方案。**

不是要求 mixed 在显存宽裕时击败 CP1。低 CP 配置在目标负载下已经 OOM，就应从性能基准中排除，只保留为容量边界记录。上一版把 64K、两层 attention、显存宽裕的统一 CP1 速度作为主裁决，偏离了研究问题。

每个 workload 点先固定 W、G、S、模型结构、训练目标和共同的显存上限 M，再选择：

\[
T^*_{\mathrm{fixed}}(M)=\min_{c:\,P_{\mathrm{fixed}}(c)\le M} T_{\mathrm{fixed}}(c).
\]

Mixed 在同一预算下与该可行 fixed 基线比较：记录速度提升、峰值差和剩余显存。若多个 fixed CP 都可行，选择其中最快者；不能任意挑一个更慢的高 CP。若 mixed 超过 M，即使只多几百 MiB，也不算该预算下可行。

“不大幅影响显存”首先意味着不突破共同硬上限，随后同时报告绝对增量 GiB 和相对增量；不把“低于 5%”自动当作极限显存下的通过标准。

全局负载相同不要求所有布局具有相同局部 batch，但必须清楚记录 B、A、DP、CP，并维持相同独立样本及有效 token 数。固定 G 的一次前反向与固定 G 的完整 optimizer step 分开评价。

## 3. 核心研究判断

需要回答的是：**能否让迫使 fixed 使用高 CP 的显存瓶颈继续保持高 CP，同时让其余模块降 CP，把节约的时间留下，而只引入可承受的额外驻留？**

HCA 在 B1 单算子曲线上表现出很好的延迟与显存缩放，CSA 当前 CP>1 路径成本较高，提供了寻找上述分工的动机。但真实模型中究竟由哪一层/哪一阶段迫使 fixed 升 CP，需要峰值时刻证据，不能预先认定就是 HCA。

还要注意固定 G、一次整体前反向的等长 THD harness 中，每 rank 本地 token 数为 G×S/W，并不随 CP 增大自动减小。因此不能把固定 B1 的显存曲线直接外推到 fixed-G mixed 栈；应实测每个布局的活跃张量、临时 workspace 和保存激活。

现有 metadata-only 转换是等长 contiguous THD 下有价值的低开销实现，应保留并测清边界。没有 tensor 搬运不等于整个布局改变没有成本，代价还可能来自 attention 内部的压缩、索引、通信和 activation lifetime。此前 117 ms 残差混合了不同 G，不能用来认定 cohort pack/switch 开销。

## 4. 下一轮主线：先建立显存受限的成对证据

### 阶段一：找到容量边界，不做 CP1/CP8 速度竞赛

- 固定 8 卡和一个共同 G；attention-only 延续实验可先用 G=8，所有候选保持一致。完整训练沿用真实目标 G，不用另一个 G 的数据替代。
- 从当前 S=64K 出发，在同一模型系列内提高序列长度，或按真实模型增加 decoder 深度，形成低 CP fixed 不可行而高 CP fixed 可行的压力点。每一对 fixed/mixed 的 S、深度和层比例必须完全相同。
- 更低 CP 先只做容量探测；OOM 后保留原因，不要求其参与速度比较。成功跨越初始化、前反向和相应 optimizer 状态驻留，才判该训练点可行。
- 查清峰值来自 CSA、HCA、FFN、输出头还是跨层激活积累。若当前两层 attention 栈无法体现目标容量约束，就进入真实 decoder 周期，避免反复扩大同一种微基准。
- 冻结共同 checkpoint/重算策略和显存余量规则；不能只给某一个方案改变负载或策略。若随后允许各方案调优，应给双方相同机会并另列结果。

退出条件：得到明确的 fixed 可行集合及约束性瓶颈，确定该压力点的最佳可行 fixed 基线。

### 阶段二：只筛选少量 mixed 候选

- 若压力点需要 fixed CP8，优先试 CSA4/HCA8、CSA2/HCA8；CSA1/HCA8 仅在剩余容量允许时追加。
- 若最佳可行 fixed 是 CP4，优先试 CSA2/HCA4；不强行使用 fixed CP8 作比较。
- 同 G 下重新测量候选的峰值增量。现有 +0.74/+0.86 GiB 仅是对应旧负载的观测，不能当作长序列/多层模型的常数。
- 若 mixed 接近或突破显存上限，定位峰值时仍存活的张量及保存时间，优先处理有证据的额外驻留；不能先把全部差额归给转换。

每个压力点先 1 个最佳可行 fixed + 至多 2 个 mixed，做短筛选；保留可行且有收益者，再各做 3 次独立重复。正式性能不带 profiler，诊断单独采集。先一个边界点闭环，再到第二个长度或深度验证边界是否稳定。

### 阶段三：交付显存约束下的收益，而非无约束最快点

主表必须含：W/G/S/层结构、显存预算、fixed/mixed CP、局部 batch/累积、可行性、完整目标区间耗时、有效吞吐、全 rank 峰值、剩余容量、增量 GiB/%、独立重复范围。

主结论形式应为：“在 S/L/G 和 M 预算下，更低 CP fixed 不可行，mixed 相对最快可行 fixed 提升 X%，峰值增加 Y GiB，仍保留 Z GiB 余量。”现阶段 X/Y/Z 不填预测值。

如果只在局部子图成立，先报告子图收益；再在相同结构的真实 decoder 和完整训练中确认参数/梯度通信及 optimizer 不抵消收益。是否需要 cohort/TMF，由目标执行方式的 batch 自由度和驻留瓶颈决定，不由 CP1 是否更快决定。

## 5. CSA teacher：保留为解释和优化支线，不阻塞容量实验

已有 32 份 trace 的重算仍有效：CP2 的 `_csa_compressed_lse_thd_kernel` 每 rank 耗时约 435–450 ms，占该 rank kernel 时长和约 63%–65%；λ=0 仍执行 teacher 的源码证据也成立。

它意味着当前 fixed 高 CP 的部分成本可能来自具体实现，值得受限消融；但不能因此把研究主线改成“必须先完成 CSA 修复，才研究 mixed”。

- 原版即可先建立显存受限的 mixed 证据，并说明实现背景。
- λ=0 修复独立推进，保留 indexer/Top-k、attention 及必要 backward/通信语义。
- 修复若进入使用，两侧 fixed 和 mixed 同时更新，只复测容量边界附近的竞争配置，不因一次修复重扫所有历史点。
- λ>0 的真实训练目标保留 teacher，不能借删除训练目标取得加速。
