# 面向 Hybrid 模型的序列与层联合动态上下文并行

2026 年 10 月 16 日讨论初稿

**摘要。** 长上下文训练需要根据输入长度分布动态分配并行资源。随着模型从重复堆叠同类注意力层的 GPT 架构，发展为结合全注意力、稀疏注意力及线性或状态递推算子的 Hybrid 架构，同一输入在不同层中的计算量、通信依赖和激活存储需求呈现显著差异。跨层沿用统一 CP 划分的调度方式难以同时适应这些差异：扩大每卡容量可能减少部分层的通信，却增加其他层的激活负担；分别选择各层的最优并行规模，又可能被层间搬运及共享显存约束抵消。为此，我们提出序列与层联合的动态上下文并行方法，将完整输入的组批、分层 CP 组和 token 放置纳入统一决策，通过算子与拓扑相关的性能响应及完整训练显存模型，选择满足预算且完整更新成本较低的执行计划。该方法保留原生调度方案作为候选，使容量适配与分层并行能够按输入需求共同发挥作用。以 GQA/GDN 混合模型为首个验证实例，16 张 H800 上的初步容量消融表明，在 72 样本长短混合输入中，相比已测容量候选中最佳的原生方案，有效吞吐提高 24.09%，峰值显存仅增加 3.34%。该结果支持通过联合优化序列分配与层间并行，在接近原有显存占用的条件下获得简单容量调整之外的训练收益。

**论文要回答的问题。** 从 GPT 到 Hybrid，dynamic CP 需要同时适应输入分布变化和层间计算机制差异。全注意力、不同模式的稀疏注意力、线性或状态递推算子，对计算与通信的需求不能只由序列长度统一描述。例如，稀疏注意力还需要考虑实际参与计算的连接、分块分布及跨卡依赖；状态递推算子需要考虑状态传递与顺序约束。MLP 则需要结合 token 负载与激活存储来安排放置。因此，同一批输入在不同层上可能需要不同的并行规模和设备分组。

以作为对照的原生调度器 N 为例，它在给定每卡容量 K 后，根据当前完整输入决定组批与 CP，并在相关层之间沿用分组及 token 归属。即使 K 跨迭代固定，N 的计划仍可随输入变化。允许逐迭代调整 K，能够进一步改善容量利用率；但增大 K、减小 CP 时，会同时提高多个层的每卡负载。因此，某个容量可能有利于部分层的通信，却使其他层及跨前后向保存的激活共同形成显存瓶颈。另一方面，独立优化每一层也不充分，因为相邻层之间的数据搬运、执行依赖以及同时存活的激活会共同决定完整更新时间与峰值显存。

我们的核心思路是把这种跨层绑定放开：**在同一完整显存预算下，让不同层选择合适的 CP 与 token 放置，并联合调整组批，使收益覆盖必要的数据搬运。** 对通信扩展性较差的区段，可以考虑较小的 CP；对需要分摊激活或计算的区段，可以考虑较大的 CP。实际选择取决于算子、输入、内核实现和设备拓扑，联合求解也允许相邻区段保留相同布局。研究目标是构建能够表达并选择这些组合的调度方法。

**方法论。** “二维”包含两个相互影响的决策维度：序列维决定完整输入如何组成微批、如何 packing，以及多个 CP 组如何并行处理样本；层维决定各相容层区段的 CP 组和 token 放置。层间选择会改变可容纳的组批，而组批又改变各层负载，因此需要联合求解。

1. **用算子约束构建可执行计划。** 为各类算子描述合法的 CP 规模、设备分组、token 布局和前后向依赖，再用统一计划连接样本归属、层区段及边界路由。调度保持模型原有的注意力连接、因果关系和状态依赖，在相容区段内复用布局，并显式计入必要边界的前向搬运与反向梯度路由。MLP 参与 token 放置与显存决策。扩展到不同稀疏注意力时，需要接入对应内核支持的划分与通信方式。

2. **用算子响应预测完整更新时间。** 模型同时描述输入规模、实际计算结构与并行拓扑：全注意力可使用长度平方和等特征，稀疏注意力需补充有效连接或活跃块的分布及通信范围，状态递推算子需描述 token 数、状态规模及传递成本。结合实测 CP 响应，估计各层、MLP 和边界转换的成本。优化对象包含完整前后向、梯度同步和 optimizer，并考虑通信重叠、rank 等待及计算通信争用；算子复杂度和稀疏率不能直接等同于完整训练加速比。

3. **以完整训练显存约束容量。** 评估模型状态、跨前后向保存的激活、workspace 和搬运暂存的同时存活峰值，并保留外部占用与安全余量。容量由具体计划的存活量决定，不能只用单层 tokens 或单层峰值代替。对预测时间近似的候选优先选择较低峰值，避免仅为减少少量微批而制造大包显存。相同物理预算下的最佳吞吐是主要比较口径。

4. **联合搜索，并保留原生 N 选项。** 对完整输入独立生成二维候选，同时评估不同容量的真实原生 N 计划。使用有界候选搜索与重复输入的计划复用控制决策成本；只有二维的预计节省覆盖额外决策、切换成本及误差余量时，才选择二维，否则执行相应容量的 N。已有分层执行、成本模型及离线求解，实际在线 N/二维分支选择仍需接入。

**性能模型如何指导调度。** 模型将输入特征转化为候选计划的边际收益与显存需求。以当前验证实例为例，对一组序列令 S=ΣLᵢ、Q=ΣLᵢ²，可写为：

$$
\widehat T_{\mathrm{GQA}}(p)=\frac{aQ+bS}{p}+R_{\mathrm{GQA}}(p),
\qquad
\widehat T_{\mathrm{GDN}}(p)=\frac{cS}{p}+R_{\mathrm{GDN}}(p).
$$

R 随输入形状、布局和拓扑变化，表达实际执行中的非理想扩展成本；其中已包含的通信不能重复计费。扩大 CP 的预测延迟减少量为：

$$
\Delta T_{\mathrm{GQA}}(p_1\!\to\!p_2)
=(aQ+bS)(1/p_1-1/p_2)
-[R_{\mathrm{GQA}}(p_2)-R_{\mathrm{GQA}}(p_1)].
$$

固定总 tokens 时，增加超长序列会提高 Q/S，使 GQA 扩大 CP 的潜在计算收益上升；中长序列占主要工作量时，线性工作相对权重提高。最终选择还取决于通信、并发、布局转换和显存，不能直接按“中长”或“超长”标签规定哪类层使用较大 CP。不同层的 CP 也不是固定总和的资源配额。稀疏注意力需要进一步用有效连接或活跃块描述工作量和依赖。

H100 当前实现以硬件独立的算子有效吞吐表达上述响应。令 W_o(S,Q) 为声明口径下的有效 F+B FLOPs，L₀=256Ki、A_o,p 为实测模块时间，采用 `C_o,p=W_o(L₀,L₀²)/(p*A_o,p)`、`T_o(S,Q,p)=W_o(S,Q)/(p*C_o,p)`。GQA/GDN 的 CP8→16 每卡效率保持率分别为 75.82%/91.81%，CP16→32 则为 69.02%/67.50%；响应必须按算子和 CP 段分别记录，不能把 GDN 在第一段的优势外推到所有 CP。CP8 聚合取两个节点中位数的中位数；GDN CP32 经方差复核后合并全部十次取中位数；锚点已包含模块通信。跨长度/packing 工作量缩放与 CP1/2/4 的 CP8 效率外推仍是未验证假设，新增配置最高支持实测 CP32。H800 数据与模型独立保留，具体公式和来源见 [模型合同](../experiments/sequence_dynamic_cp/JOINT_CP.md)。

调度器将各微批、各区段的并行组最大成本与前后向转换、其他训练项组合，再按完整存活显存筛选计划。因此，模型既指导候选选择，也指导实验设计：例如固定总 tokens 改变长度分布以检验平方项影响，或在相同输入规模下改变稀疏连接结构以检验通信依赖。H800 模型含迁移先验，H100 模型含单长度外推；两者仍有粗略执行项，overlap、到达等待及争用尚未充分表达，需要用候选排序和所选计划的实际表现检验其指导能力。

对相同有效输入 x，令 G(P) 为计划分配的总 GPU 数（含等待的卡），可以将目标简写为：

$$
\min_{P\in\mathcal P_N(x)\cup\mathcal P_{2D}(x)}
G(P)\bigl[T_{\mathrm{update}}(P,x)+T_{\mathrm{decision}}(P,x)\bigr],
\qquad M_{\mathrm{required},r}(P,x)\le B_r\quad\forall r.
$$

其中，N 候选覆盖声明的容量集合，二维候选联合改变组批与层布局；完整更新时间已经包含实际数据转换。所有计划必须覆盖相同输入并保持相同训练语义。当前求解在固定 G 下进行，因此时间与 GPU·时间目标等价。有限候选搜索提供可执行解，不据此宣称全局最优。跨迭代主评价采用总有效 FLOPs 除以总 GPU·时间及对应 MFU，另报告 tokens/墙钟，计入规划与切换；回退机制旨在降低性能退化风险，其效果仍需在线验证。

性能收益以按分配 GPU 数归一的每卡有效 TFLOP/s 或 MFU 判断。相同工作量与硬件下，效率比为 `(p_old*T_old)/(p_new*T_new)`；卡数翻倍而时间未减半是效率下降，不能仅凭单组延迟下降宣称收益。完整计划计入所有分配卡及等待，在线还计入决策与切换。本文已有固定 16 卡、相同输入的完整训练对照，其时间/吞吐排序与每卡效率排序等价；跨卡数比较必须显式归一。

显存与速度的交换可作为额外部署偏好：相对同一预先固定参考，若显存增长为 m、有效吞吐增长为 g，则要求 g≥αm，当前 α=2，可调整。N 调容量与二维共同遵守，物理显存预算始终独立约束。论文保留不同显存预算下的吞吐结果，使方法价值不依赖某个特定 α。

**当前实例与初步证据。** 首个验证实例采用 GQA 与 Gated DeltaNet（GDN）的混合结构，用于检验层间 CP 选择是否能获得简单容量调整之外的收益。72 样本输入由 8 条 256Ki 长序列和 64 条 4Ki 短序列组成。模型为 8 层，BF16、无重计算，在两节点共 16 张 H800 上执行完整训练更新。连续 GDN 区段连同其中的 MLP 始终保持 contiguous，段内不进行 contiguous 与 zigzag 的往返转换。这里的原型运行在 GPTModel 容器中，尚未完成到独立 HybridModel 类的集成。下表中的 CP 指长序列所在组，显存报告全卡最大 allocated 峰值。

| 方案 | GDN / GQA CP | 完整更新均值 | 全卡 allocated 峰值 | 结果 |
| --- | --- | ---: | ---: | --- |
| 原生 N，K=16Ki | 16 / 16 | 18.253 秒 | 42.761 GiB | 最佳已测 N |
| 原生 N，K=24Ki | 16 / 16 | 20.172 秒 | 57.045 GiB | 微批减少，但更慢且显存更多 |
| 原生 N，K=32Ki | 8 / 8 | 无有效计量窗口 | 70.114 GiB | 完整更新后被共同显存保护拒绝 |
| 二维联合计划 | 16 / 8 | 14.709 秒 | 44.188 GiB | 时间降低 19.42%，吞吐提高 24.09% |

K32 虽然让 N 的长序列 GQA 也进入 CP8，却使其他层同时承担更高每卡负载；计入外部占用后的 required 峰值为 77.382 GiB，超过共同预算 71.179 GiB。这是预算拒绝，并非 CUDA OOM。二维计划保留 GQA CP8，让 GDN 使用 CP16，并将 MLP 的 token 分布在 16 卡上。由此，在已测 K16/K24/K32 中，简单调容量没有带来收益，二维保留了额外增益；取消 α 偏好也不改变这个结论。该消融支持分层自由度的价值，整步增量仍包含组批、放置及路由的共同作用。

568 样本输入提供了补充证据：降低纯短序列组批的大小后，二维峰值从 56.638 降至 44.591 GiB，时间仅增加约 0.33%；相对固定 K16 的 N，仍有 24.82% 吞吐提升，显存只增加 3.43%。它说明这批实验中的主要收益可以在相近显存下保留。

新的 224Ki 长短混合输入进一步区分了两类收益：固定 N-K24、可变 N-K14 与二维的完整更新时间分别为 17.954、16.089 和 12.444 秒。容量适配提高吞吐 11.59%，二维在可变 N 之上再提高 29.29%，allocated 仅增加 3.37%。这说明在当前实例中，二维收益并未被逐输入容量调整替代。

同日的 H100 迁移实验给出反例：沿用相同输入和冻结二维计划，224Ki、不规则长度、192Ki 三组的二维更新时间为 10.021、9.612、8.081 秒，已测最快原生 N 为 6.519、6.557、4.815 秒；每组也存在比二维更快且 allocated / required 更低的 N 候选。224Ki 同一 N-K14 计划改用 joint executor 仅慢约 1.26%，不足以解释原二维计划约 53.72% 的时间增量。该结果限制了旧计划和 H800 响应先验的可迁移性，尚不能排除 H100 重新求解后的二维收益；后续需独立校准与保留输入验证，不能将 H800 正例写成跨硬件普遍结论。随后固定 256Ki 的模块实测进一步确认：H100 GQA 的 CP8→CP16 延迟比为 1.50–1.53×，与旧 H800 同长度的变慢方向相反；当前 GDN chunkwise 的延迟比为 1.81–1.87×。但两者每卡 TFLOP/s／MFU 分别降至 CP8 的 75.10%–76.54% / 90.28%–93.34%，按资源归一的指标均没有性能收益；同时仍缺少同配置 H800 GDN 对照。这是单长度锚点，跨长度与 packed 输入校准仍待完成。完整结果见 [当日归档](ARCHIVE-20261016.md)。

上述数据来自短运行及复用的不同启动窗口，属于初步完整训练性能证据；本轮未进行数值等价对比，也未测得在线规划后的净收益。容量对照是有限集合，不能推广为超过所有可能容量的 N。

**论文贡献与后续验证。** 贡献可以组织为三个相连的部分：刻画异构算子的 CP 响应、层间连接成本与共享显存约束；构建遵守各类算子计算依赖的分层执行和完整更新成本模型；据此联合选择组批、CP 组及 token 放置，并保留原生 N 的执行选择。每一部分都服务于同一个问题：如何把 Hybrid 模型中不同层的扩展性差异转化为受显存约束的完整训练吞吐收益。

关键消融应依次比较合理固定容量的 N、逐输入可调容量的 N，以及允许选择 N 的二维方案。前两者之差衡量容量适配，后两者之差衡量二维的额外价值。近期固定 GDN:GQA=3:1 并验证变化的输入分布，之后再扩展到不同稀疏注意力模式，观察哪些计算与通信结构需要分层选择，哪些场景通过调整 N 的容量即可获得较好性能。每个模型内的对照须保持相同注意力模式、输入与训练目标，以检验调度本身的收益。

性能模型的独立消融应固定候选集合、执行器和共同显存规则，比较简单计算量评分与包含算子 CP 响应、转换及完整显存的评分，观察预测排序和最终所选计划的实际收益。容量与二维的消融衡量调度自由度，这项消融衡量模型能否用好这些自由度。

CP32 后续筛查使用新的模块响应，在 33 个输入/卡数组合中独立求解二维并比较真实 N 的有限容量集合。当前完整对照内最佳预测增益仅约 1.08%，来自 16 卡不规则输入，表现为少数微批 GDN CP16 合并、GQA 两个 CP8 分组，并降低模型峰值；该弱正例另通过区间内全部 32-token 对齐 N 容量扫描。32 卡未找到有意义且对照完整的优势候选。这些仍是有界 CPU 搜索与未完整校准的预测，不构成新的训练性能正例，也不证明二维空间没有更好方案。

当前已完成 GQA/GDN 实例的分层执行、有限容量消融及 H100 迁移评分诊断；优先补足 H100 跨长度/packing、执行成本和显存校准，再做评分消融并扩展稀疏注意力。还需接入在线选择，计入决策和切换成本，验证收益不足时的 N 选择，并补足训练正确性证据，进而评价整个调度器的净收益。
