# 随机 global batch 下的固定容量 N、可变容量 N 与二维（3:1）

2026-10-16。按用户澄清：连续 GDN 布局要求仅约束 baseline N；二维保留现有分层 CP、组批和 MLP token 放置自由度。模型固定为 GDN:GQA=3:1，当前为 8 层 `GGG*GGG*`，其余形状、16 卡拓扑和显存预算沿用既有合同。

本次是分析与 CPU 评分，没有 GPU 启动。复用上一轮 3:1 候选缓存，仅新增一份 **N-K15.5Ki** 计划及两种响应政策下的评分。此前对二维施加严格布局约束、以及 7:1/1:1 层组成的结果不作为本分析的主对照。

## 1. 比较对象与容量含义

- **固定容量 N**：训练全程使用一个统一 K；每个 global batch 仍按其完整输入运行原生 `next_hdp_group_packing_aware`，重新分配 CP 和 packing。本分析允许先知道输入分布，从候选域选全分布平均成本最低、对所有支持输入可行的 K；因此不是只与固定 K16 比。
- **可变容量 N**：每个 global batch 根据当前完整输入选择一个统一 K；不根据未来 batch，不改变原生 n²/CP、greedy/fill、tie-break、rank 放置。同一条序列在 GDN/GQA 中沿用同一 CP。这里不包含每个微批各自选不同 K 的更强变体。
- **二维**：使用现有二维候选的完整自由度，包括 MLP 重分布；离线比较允许选 N。实际在线 N/二维分支及净收益尚未实现或测量。

N 本身允许同一 batch 中不同样本采用不同 CP，也会 packing。不能把“混有不同长度”直接解释成 N 不支持。容量 K 只须满足实现的 token 对齐要求，不必是 2 的幂；合法 CP 组大小在当前 16 卡配置仍为 1/2/4/8/16。

普通和 mixed DUPC 路径的 GDN 段内没有 contiguous↔zigzag 往返，5 份既有 N 计划与当前 Megatron 原函数一致。证据保留在 `../joint_advantage_search_20261016_r1/audit.json`，本次未重复 GPU 核对。

## 2. 一个简单的可变容量算法

对当前 batch 的长度集合，构造：

```text
K_candidates = {16Ki} ∪ {ceil_to_32_tokens(L_i / p): p ∈ {1,2,4,8,16}}
```

在声明的容量范围内，对这些 K 分别运行原生 N；用共同成本/完整显存模型排除不可行候选，再选预测时间最短者。原生 packing 不接收二维评分，不修改工作量函数。它是一维小候选搜索；当前样本各有 2–10 个容量候选。评分仍使用共同模型，不能据此宣称规划已经廉价或在线可用。

该规则覆盖原生最小 CP 变化的阈值，但不穷尽 packing 工作量上限引起的所有变化。为避免只比较一个弱 heuristic，同时保留逐 batch 最佳的有限容量对照：K8–K40、步长 1Ki，再补上述非整数 Ki 阈值。本次新增 248Ki/16=15.5Ki；没有把容量向 2 的幂或整数 Ki 强行取整。

在本次 11 个支持输入、两种 CP16 响应政策、物理预算/α=2 两种口径中，小候选规则均与有限容量对照选出相同的最短预测时间。这不是对任意输入或全部 32-token 对齐容量的最优保证。

## 3. 随机性如何影响比较

对随机完整输入 B，可将两类收益分别定义为：

```text
T_fixed = min_K E[T_N(B,K)]                         # K 对支持输入均可行
T_adapt = E[min_K T_N(B,K)]                         # 每批可行的容量集合
T_select = E[min(best_native(B), best_joint(B))]

容量适配节省 = T_fixed − T_adapt
二维额外节省 = T_adapt − T_select
有效吞吐 = E[有效 tokens] / E[完整更新时间]
```

这是理想/离线选择关系。实际简单算法有选择损失，实际执行还需规划、切换和等待成本；不能直接用上述模型结果宣称在线不退化。

**batch 内随机性**改变长度多重集合、S=ΣL、Q=ΣL²、CP 阈值和 packing 余量。只打乱同一批样本的次序不会产生新的长度分布；N 会按长度排序，二维可用完整池组批。

**batch 间随机性**使各 batch 的最佳 K 变化，通常为可变容量 N 提供机会。但如果所有 batch 都来自同一个分布且样本数很大，直方图可能很稳定；随机性本身不保证容量调整或二维有明显收益。若最佳统一 K 在各 batch 上相同，容量适配增量也可为零。

当前没有跨步状态项。相同 batch 集合随机重排不改变预测总时间，不能把它解释为已验证的分布切换收益。无需预测下一批：三种方法都获得相同的当前完整输入元信息。

## 4. 可量化的有限支持随机输入分析

复用缓存中 11 个完整、可评分的 3:1 输入。随机模型为：每个 global batch 独立抽取一个长度多重集合，再随机排列其中的样本。它允许 batch 内、batch 间随机，**不是逐条独立抽样长度的全面测试，也不是实际训练数据的分布估计**。对声明概率精确求期望，不做 Monte Carlo，不平均逐 batch 的百分比收益。

排除另外三种层组成；224Ki＋8Ki 输入因 N-K29 的 mixed-partition 评分未支持而保留为未决，不将其静默视作物理不可行。

主要报告共同物理模型预算 71.178833GiB 下的性能。峰值含 external=7GiB 和 margin=2GiB，是模型完整训练峰值，不是实测 allocated。α=2 另列，始终相对同输入 N-K16 的共同固定参考，不重置参考。

## 5. 二维在可变容量之后仍可能有优势的场景

### A. GQA 希望节点内 CP8，GDN/MLP 仍需要跨 16 卡分摊

K 任意变化仍然是一个标量。同一条长序列若在原生 N 中从 CP16 降到 CP8，GQA、三倍数量的 GDN，以及跟随层布局的 MLP 会一起改变；K 本身不能表达 GDN16/GQA8。二维可以分别决定，并支付边界与 MLP token 重分布成本。

在当前 8 卡/节点拓扑和冻结响应中，GQA CP8 优于 CP16；但 N 把 224/240/248/256Ki 长序列降到 CP8，分别至少需要 K28/K30/K31/K32，统一层布局带来的完整激活/工作区可能超过预算。二维保持 GDN16、GQA8、MLP 较均衡的 token 放置，可能保留收益而降低峰值。**这是当前最明确的结构性线索；不是容量只能取 2 的幂造成的。**

每项默认 8 条长序列＋64 条短序列、3:1 模型。下表对照逐 batch 最佳已评分 N，只有物理模型预算：

|输入|可变 N 的 K|二维预测吞吐提升|模型峰值 N→二维 GiB|
|---|---:|---:|---:|
|224Ki＋4Ki|14Ki|30.63%–35.06%|48.650→51.143|
|240Ki＋4Ki|15Ki|29.41%–31.61%|50.447→53.089|
|248Ki＋4Ki|15.5Ki|28.88%–29.98%|51.345→54.062|
|256Ki＋4Ki|16Ki|28.41%|52.244→55.035|
|256Ki＋8Ki|16Ki|27.30%|52.244→55.447|
|256Ki＋16Ki|16Ki|25.27%|52.244→56.271|

这些结果不要求二维取消 GQA MLP 往返；相关开销已计入。原有 72 条输入的真实 K32 预算拒绝可作为对应输入的实测支持，其余长度的大容量 N 仍是模型判断。

### B. 同一 batch 中长序列长度跨度较大，GQA 与线性工作量的负载目标不一致

GQA 的平方工作量和 GDN/MLP 的线性工作量可能由不同样本群主导。原生 n²/CP packing 与一个共同 K 可改善平衡，但无法直接按不同层重组样本、重置 rank/token 放置。二维可能通过重新组批及分层放置降低完整步时，而不只通过阻止 N 用大 K 获益。

例：[160,192,224,256]Ki 各 2 条＋64×8Ki。可变 N 选择 K24，物理模型可行；二维相对它预测吞吐 **+12.82%–+28.77%**，模型峰值 **66.621→55.447GiB**。这比仅以“大容量 N 超预算”为依据更值得独立验证。

这里只说明该完整联合候选有优势，尚未因果分离 packing、逐层 CP、MLP 放置和路由的贡献；也不是所有高方差分布都会获益。

### C. 长尾形状随机出现，收益占比足以覆盖额外规划与切换

若部分 batch 可由调容量后的 N 充分处理、另一部分需要分层决策，二维应允许选 N。q 表给出一个明确示例：二维额外价值来自有利输入上的完整成本差，不来自“随机”这个标签。

实际在线成立需要平均执行节省覆盖相对可变 N 的额外规划、缓存未命中、切换和误差余量。这些成本目前未测量；表内全部按零额外在线成本计，不能直接称为部署净收益。

### 反例：容量适配已经足够

192/208Ki＋4Ki 分别选 K24/K26 后可使用 CP8。当前二维构造反而慢，吞吐相对该 N 约低 33.62%/34.32%，所以离线选择返回 N。N 原生支持多 CP 与 packing，随机长短混合也可能完全落在这种范围内。

## 6. 当前结论与下一验证优先级

应先把固定容量 N 调到对整个声明分布合理的值，再比较可变容量 N。后者必须保持原生调度，仅增加一维 K 选择，而且不能被人为限制为 2 的幂。本次 K26 固定对照与 K15.5 可变候选说明这两点会实际改变比较。

二维的优先正例是 **224Ki＋4Ki 的算子/显存冲突**和**不规则长序列＋8Ki 的可行 N 对照**；保留 **192/208Ki** 作为应选 N 的反例。所有模型固定 3:1。先用同一批输入的固定 N、可变 N、二维拆分容量收益与二维增量，再讨论随机流中按概率加权的有效吞吐。

本次不安排 GPU 运行。成本系数、packed/GDN CP16 响应、head 数迁移和显存模型沿用原局限，没有重新拟合。容量域仍有限，二维仍是有限构造候选；当前数据不证明超过任意整数 K 的全局最优 N。

复现入口：`experiments/sequence_dynamic_cp/random_batch_capacity_analysis.py --output <新目录>`，使用 `/workspace/envs/flagscale/bin/python`。`analysis.json` 保存全部输入、概率、候选、选择、排除原因及 K15.5 新计划。容量非二次幂阈值、期望吞吐计算、单一固定 K 和选择 N 的行为已通过针对性 CPU 测试；共 9 项通过。
