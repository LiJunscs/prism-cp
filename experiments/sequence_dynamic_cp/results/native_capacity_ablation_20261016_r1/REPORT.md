# 最小容量消融：二维相对动态容量N的增量

在72条输入、K∈{16,24,32}Ki的有限对照中，原生N仍选择K16；复用的二维结果保持19.42%的完整更新时间降低、24.09%的吞吐提高，allocated峰值仅增加3.34%。扩大N容量到K24使时间和显存均增加；K32虽能让长样本改用CP8，但真实完整更新后超过共同显存保护预算。

这个结论在不施加α=2偏好、仅保留物理显存约束时也成立，因此不是通过任意交换阈值排除更快N而得到的优势。它支持该case中二维具有简单容量修正之外的额外价值；未穷举所有K，也未验证在线输入分布切换。

## 最小矩阵与实测

输入保持8×256Ki长样本和64×4Ki短样本，共2,359,296 tokens、1,179,648有效loss tokens。模型保持8层GGG*GGG*、H4096/FFN16384、GQA32Q/8KV、GDN16×128、BF16、TP=PP=1、无重计算。每步完整执行F/B、梯度finalize、clip、Adam及参数同步；GDN段含MLP保持contiguous。

|---|---|---:|---:|---:|---:|---|
|原生N-K16，复用|16/16|9|18.252830|42.760971|49.165390|可行、最佳已测N|

reserved峰值：N-K24为63.720703GiB，N-K32为72.957031GiB。reserved不与allocated相加。共同物理保护为min(设备总显存90%,设备总显存−8GiB)，本次各rank预算均为71.178833GiB；required使用allocated峰值加既有运行记录中的外部占用。

K24的第3–5步rankMAX时间为20.184849787、20.138744239、20.193230309秒，均慢于原N的全部3个计量步（18.248838–18.256268秒）。平均时间增加10.52%，吞吐下降9.52%，allocated增加33.40%。α=2要求吞吐至少提高66.81%，故拒绝该容量选择；即使取消α偏好，它也不会替代更快的K16。

K32的16张卡全部完成第1次完整更新，输入、有效loss tokens、完整F/B、非跳过Adam、有限值及参数同步均通过。所有卡的本地required都超过预算，超额范围5.671–6.203GiB。随后训练按既有保护退出1；这是完整更新后的预算拒绝，不是CUDA OOM。没有完成预热和计量窗口，不报告K32的性能、速度比或α交换结果。

二维相对最佳已测N：时间减少3.543953秒（19.415908%），吞吐提高24.093972%，allocated增加1.426788GiB（3.336660%）。α=2需要的吞吐增长为6.673321%，因此二维通过。

## 计划差异与消融解释

N始终使用原n²/CP、greedy/fill和原生DUPC，不安装joint adapter。生成及执行只改变K：

- K16：8个单长样本CP16微批，另1个纯短CP1微批。
- K24：将64条短样本填入2个CP16长样本微批，每批1长+32短；其余6个微批各1长。微批减少为8，但整步更慢，说明增大容量、减少微批不能替代合适的层与组批选择。
- K32：4个微批各在两个节点以CP8同时执行2条长样本，另1个纯短CP1微批。长样本在GDN/GQA/MLP各层均承担32Ki/rank，实际完整训练显存越界。
- 二维：长批GDN16/GQA8，MLP分布在16卡。它保留节点内GQA CP8的选择，同时分摊其他层的负载；真实峰值显著低于N-K32。

按固定N→最佳已测容量N→二维顺序，本case简单容量修正增量为0，二维额外节省3.543953秒。端到端增量仍包含组批、放置和路由的共同影响，不能当作逐算子因果分离或全部K上的最优性证书。
